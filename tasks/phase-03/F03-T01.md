# F03-T01 — تصميم وتنفيذ migrations للهوية والأدوار

- **المرحلة:** F03 — قاعدة البيانات والمصادقة والصلاحيات
- **الحالة:** NOT_STARTED
- **الأولوية:** P0
- **الهدف:** إنشاء profiles وstaff roles/permissions بمخطط قابل للترحيل.
- **النطاق/المخرجات:** database migrations
- **المتطلبات السابقة:** بوابة المرحلة السابقة F02
- **الاعتماديات:** قرار التقنية والنطاق في `../../DECISIONS.md`؛ ومعايير المجال ذات الصلة في `../../REQUIREMENTS.md`.

## قيد البيئة لهذه المهمة
- التنفيذ والاختبار محليان فقط؛ قاعدة البيانات محلية، وبيانات اصطناعية. لا نشر ولا Supabase Cloud ولا مزود خارجي.
- إذا استدعت المهمة خدمة خارجية، نفّذ الجزء المحلي المستقل فقط، وسجل الجزء المتبقي ومعيار استئنافه في `../../DEFERRED_EXTERNAL_INTEGRATIONS.md`؛ لا تعتبر المهمة مكتملة مع بقاء معيار أساسي غير محقق.

## خطوات التنفيذ
1. اقرأ الوثائق المرجعية ذات الصلة وافحص الحالة الحالية قبل التغيير.
2. ثبّت مدخلات المهمة والحدود وافصل أي تغيير متطلبات عبر `PROPOSED_CHANGES.md`.
3. نفّذ المخرج المحدد فقط، مع تحقق خادمي وخصوصية وأمن مناسبين للمجال.
4. أضف الاختبارات المطلوبة وسجّل نتائجها الفعلية؛ لا تكتفِ بنجاح البناء.
5. حدّث الحالة والسجلات والتقرير، واربط أي عيب بمهمة إصلاح مستقلة.

## معايير القبول
- FK/قيود وفصل مستخدم/موظف واختبار ترحيل نظيف وعكسي/ forward.
- لا أسرار/بيانات حقيقية في المستودع أو fixtures؛ وتوثيق أي قرار تقني جديد.
- جميع الاختبارات ذات الصلة ناجحة، أو موثق سبب الفشل/الحظر ولا توسم المهمة مكتملة.

## الاختبارات المطلوبة
Integration tests لمخطط وصلاحيات أولية.

## المخاطر الأمنية
تجاوز الصلاحية أو تسريب بيانات أو الاعتماد على مدخل من العميل أو التكرار؛ راجع `../../SECURITY.md` واكتب اختبارات رفض لاختراق حدود المهمة.

## النتيجة المتوقعة
مخرج مستقل قابل للمراجعة والتشغيل ضمن نطاق المهمة، وسجل أدلة قبول.

## تقرير الإنجاز عند التنفيذ
- الملفات المتأثرة: غير منفذ
- التطور البصري/الوظيفي/الأمني: غير منفذ
- الاختبارات ونتائجها: لم تنفذ
- المشاكل المتبقية/المهمة التالية: تحدد عند التنفيذ
